The same two statements returned the same two answers all three times:
the transaction read from one snapshot taken at its first statement, so
the writer's commit, under a second into A's transaction, was invisible
to it. Nothing was blocked; the cost is that A could commit a decision
based on data that is 3s old.

B held 999 uncommitted for 3s. A asked for READ UNCOMMITTED - the level
that exists precisely to permit dirty reads - and still read 1, because
PostgreSQL has no dirty reads at any level: readers see the last
committed version and never block on the writer. SHOW echoes the level
back, but the behaviour is READ COMMITTED's.
